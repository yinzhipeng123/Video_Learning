# 播放器排查与验收

应用使用课程提供方的官方 HTTPS 网页播放器。应用不提取原始视频地址，不绕过 token、授权或证书校验。初始地址与顶层页面跳转只接受以下两个精确域名：

- `e54144713.at.baijiayun.com`
- `e54144713.at.baijiacloud.com`

允许标准 HTTPS 端口（默认或 443），不允许用户信息、HTTP、相似域名或其他租户域名。官方页面可能通过 HTTPS CDN 加载子资源。

## 常见情况

| 现象 | 应用行为 | 处理方式 |
| --- | --- | --- |
| 页面 HTTP 401/403 | 显示链接可能过期或需要授权，可重新加载或返回 | 请课程提供方确认链接有效性；应用无法自行更新 token |
| 页面返回 HTTP 200，但播放器内显示过期、无权限或媒体错误 | 保留官方页面及错误信息，顶部始终有重新加载和返回按钮 | 记录课程名称及错误提示，请提供方更新可用链接；不要公开完整带 token 地址 |
| 主页面网络错误 | 显示网络提示，可重试 | 检查手机网络，恢复网络后点重新加载 |
| 主页面加载超过 30 秒 | 显示加载超时，可重试 | 检查网络或稍后重试；媒体缓冲属于官方播放器的控制范围 |
| SSL/证书错误 | 取消不安全请求并提示检查日期与网络 | 修正手机日期或网络环境，证书故障需提供方修复；应用不提供忽略证书按钮 |
| 页面 HTTP 其他错误 | 显示服务暂时不可用 | 稍后重试或联系提供方 |
| WebView 渲染进程退出 | 移除并销毁故障 WebView，显示重新加载 | 点击重新加载会创建新的 WebView |
| 非法初始地址或页面跳向未允许的域名 | 阻止加载并显示链接提示 | 请更新课程清单中的官方播放地址 |
| 页面显示黑屏但有播放时间 | 若官方播放器根元素高度塌陷，应用按 WebView 实际视口补齐页面高度，并在旋转后同步 | 使用最新 APK 重新打开课程；若仍出现，记录课程名称、系统 WebView 版本和画面 |
| 点击播放器却没有播放 | 默认要求一次用户手势 | 点击官方播放器中的播放按钮；若仍无效，检查页面的具体提示 |

## 本机进度与降级

应用优先使用已验证的官方 BPlayer 注册实例读取 `currentTime`。实例必须属于当前页面的 `#app` 容器，并通过类型、连接状态和控件归属检查。播放器就绪后，应用每约 2 秒读取真实播放时间，并通过本机存储保存。重新进入课程时，调用官方 `seek` 方法尝试恢复位置；该方法仍执行课程提供方的观看限制。恢复位置不会超出当前视频时长，拖动播放位置后也会记录新的时间。

若页面没有符合条件的 BPlayer 实例，则使用顶层文档中可访问的 HTML5 `video` 元素读取和恢复位置。

页面既未提供符合条件的官方实例，也未提供可读取的视频元素，或播放器放在不可访问的 iframe 中、元数据尚未准备好、读取失败时，应用不写入伪造的零进度，也不清除已有位置。此时保留“已打开课程”和手动“标记为已学完”的记录。应用没有推断观看时长或自动判定学完。点击画面后，会调用已验证的官方控制条显示方法；原有播放暂停、拖动、全屏和自动隐藏行为保留。

后台切换时应用停止进度轮询，通过已验证的官方实例 `pause()` 暂停 WASM 播放器，同时暂停可访问的 HTML5 音视频并调用 WebView 生命周期暂停。页面 visibilitychange 监听为后台暂停提供第二条路径，并在返回前台时抑制官方 WASM 引擎自行继续播放；学生可点击播放继续学习。离开播放页面时会销毁 WebView 及全屏视图。因为网页实现和系统 WebView 版本可能不同，实际后台音频停止行为仍需使用目标手机验证。最后一次轮询至退出之间最多约 2 秒的播放变化可能尚未记录。

## 真机验收步骤

1. 从每个课程分类各打开一节有效课程，确认官方页面加载后能点播放、有声音，并检查拖动与播放暂停。
2. 播放约 20 秒后返回详情，再次播放，确认能读取官方 BPlayer 或 HTML5 进度的课程恢复到接近退出的位置；若页面不支持读取，应保留已打开状态并可手动标记学完。
3. 点击右上角旋转按钮，确认横屏与竖屏切换后课程仍在当前播放页。
4. 点击官方播放器的全屏按钮，确认进入横向全屏。按手机返回键一次，应退出全屏留在播放页；再按一次，应回到课程详情。
5. 从全屏状态返回竖屏和详情后，确认没有遗留遮罩，手机系统栏恢复，详情没有被强制保持横屏。
6. 播放时切到桌面，确认声音停止；再进入应用，确认可继续操作。退出课程后确认声音和全屏视图均结束。
7. 断网后重新进入课程，确认出现可重试错误；恢复网络后点重新加载，确认页面恢复。
8. 使用课程提供方确认已失效的链接观察错误提示与返回操作。不要为了测试而绕过授权或修改证书验证。
9. 按课程目录的 `videoId` 对同一视频的重复课程入口，检查本机记录是否共享。清除应用数据后，记录应清空。

## 验证范围

已加入 JVM 单元测试，覆盖精确域名及 HTTPS 策略、拒绝相似域名和不安全协议、有效进度解析、无法提供进度时返回空值。具体构建和 JUnit 执行结果以本次构建报告为准。

对页面进度脚本做过 Node.js 模拟执行检查，覆盖无视频、元数据未就绪、只恢复一次、播放时间推进、时长边界、无有效时长和拖动中状态。这类检查不能证明第三方页面或真机播放可用。

2026-11-25 在 Android 15 模拟器中诊断了首条真实课程：官方 FFPlayer/WASM 播放器存在 canvas，但网页根高度和 canvas 高度均为 0，因此有播放时间却没有画面。对可信页面实施可逆的根高度修复后，截图中实际出现讲师与课件画面；同一修复已加入源码，并为 WebView 设置 MATCH_PARENT 布局参数。

这次观察证明该课程的显示问题可通过布局适配解决，不代表所有课程、音频、后台暂停或本机进度恢复均已验收。当前被观察的官方播放器未提供 HTML5 video 元素，但已验证其公开 `BPlayer.instances` 中的实例提供 `currentTime`、`duration`、`pause`、`seek` 和 `controller.show`。真实页面实测 pause 后时间保持不变，seek 可调整播放位置；公开 seek 在 WASM 内部随后可能继续播放，因此应用不会在后台执行恢复位置。实际触摸后已看到官方播放暂停、进度和全屏控制条。

新增 `node tools/test_player_bridge.mjs` 测试，对严格实例筛选、官方暂停、visibilitychange、触摸与滑动区分、时间读取、单次恢复、时长边界和 HTML5/不可读回退进行验证。完整 APK 的安装回归与其他步骤以验收报告为准，没有将桌面网络探测、JVM 测试或 APK 编译成功视为真实视频播放验收通过。

实现时已查阅 Android 官方 WebView、WebViewClient、WebChromeClient API 文档，特别是 SSL 错误取消、渲染进程退出后移除故障视图、销毁顺序、UI 线程执行 JavaScript 和全屏自定义视图回调约定。

打包后的安装、续播、全屏返回、断网和清除数据检查以 [首版验收记录](acceptance.md) 为准。全屏使用标准 DOM 全屏与 WebChromeClient 自定义视图；容器只在全屏期间接管返回事件，退出时同步清理 DOM 全屏、原生视图、方向和返回回调。
