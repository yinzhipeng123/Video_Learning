# Tasks

## 1. Android 工程与基础结构

- [x] 1.1 创建 Kotlin Android 工程、应用模块、基础主题和导航骨架，并验证 Gradle 构建可以生成 debug APK。
- [x] 1.2 建立课程领域模型、分类/列表/详情/播放页面的模块边界，并验证工程能够编译通过且页面路由可被测试访问。
- [x] 1.3 配置最低 API 级别、网络权限、横屏播放所需的屏幕方向策略和调试日志规则，并验证安装后的 APP 可以启动到首页。

## 2. 课程数据转换与校验

- [x] 2.1 编写从用户提供的 Excel 清单生成 assets/courses.json 的转换工具，并验证输出包含 3 个分类和 131 条课程记录。
- [x] 2.2 实现课程字段规范化、分钟数字与 HH:MM:SS 时长转换、百家云视频 ID 提取和稳定 ID 后备规则，并用缺失字段样例验证转换不会丢弃可浏览课程。
- [x] 2.3 增加数据质量校验，检查必填标题、HTTPS 播放地址、视频 ID 重复引用和无法解析的时长，并验证一条坏记录只产生可定位的警告。
- [x] 2.4 将生成后的 JSON 接入 APP 内置资源，并补充数据格式说明和重新导入步骤；验证 APP 不依赖网络也能加载课程目录。

## 3. 分类、列表与课程详情

- [x] 3.1 实现分类页和课程列表页，展示分类、标题、章节、教师和统一时长，并验证不同分类切换后列表内容与 JSON 顺序一致。
- [x] 3.2 实现课程详情页和“开始学习”入口，支持简介、教师职称、章节和缺失字段的容错展示，并用完整与缺字段样例验证页面不崩溃。
- [x] 3.3 实现列表到详情、详情返回列表的导航状态保持，并验证返回后滚动位置和所选分类仍然可用。
- [x] 3.4 为目录和详情页面添加 UI 测试，覆盖分类选择、完整记录、缺失可选字段和无效播放地址提示；验证测试在本地构建中通过。

## 4. 百家云 WebView 播放器

- [x] 4.1 封装独立的 WebView 播放页面，启用所需的 JavaScript、DOM storage、媒体播放和自定义全屏回调，并验证使用一条真实课程链接可以打开播放器页面。
- [x] 4.2 实现百家云 HTTPS 域名白名单、非预期跳转拦截、加载超时和网络错误状态，并验证无效地址不会导致 APP 退出且可以重试。
- [x] 4.3 实现播放页的横屏、全屏、返回和 WebView 生命周期处理，并在至少一台目标 Android 设备上验证播放控制和返回路径。
- [x] 4.4 记录 WebView 与百家云页面的兼容性限制和排障步骤，并验证文档包含 token 失效、网络失败和页面加载失败的处理方式。

## 5. 本机学习进度

- [x] 5.1 使用 DataStore 保存以稳定视频 ID 关联的最近打开时间、完成状态和可用播放位置，并验证课程排序变化不会错配已有状态。
- [x] 5.2 在课程详情和列表中显示“继续学习”和“已学完”状态，实现手动标记完成和取消完成，并验证状态在进程重启后仍保留。
- [x] 5.3 在播放器退出和页面销毁时保存可获得的进度；播放器无法提供精确位置时保留打开状态和手动完成状态，并用两种播放器能力样例验证降级行为。
- [x] 5.4 增加本机进度单元测试和清除应用数据验收步骤，验证清除数据后目录仍可加载且学习状态被移除。

## 6. 集成验收与发布包

- [x] 6.1 完成从分类、列表、详情到百家云播放和返回的端到端验收，并验证单条坏课程不会影响其他课程。
- [x] 6.2 执行课程记录数、视频 ID、播放地址和 APK 启动检查，记录 131 条课程的导入结果，并验证检查失败时构建不会静默发布。
- [x] 6.3 生成首版 debug/release APK，记录安装、播放、横屏、进度保存和错误重试结果，并验证 APK 可以在目标设备完成完整学习流程。
