# Design

## Context

项目当前只有 OpenSpec 规划目录，没有现成 Android 工程、业务模块或主规格文件，因此本 change 按绿地 Android 客户端设计。课程来源是用户提供的 Excel 清单，包含 3 个分类、131 条记录和百家云网页播放器地址；不同工作表的时长格式不一致，且部分课程章节可能复用同一个视频 ID。

课程链接是网页播放器页面，而不是可直接交给原生播放器的媒体文件地址。首版不设置账号和服务端，学习状态只需要在当前设备保存。设计目标和可观察行为以 specs/course-learning/spec.md 为准。

## Goals / Non-Goals

**Goals:**

- 建立一个可独立发布的 Android 客户端，完成分类浏览、课程详情和视频学习闭环。
- 将 Excel 记录转换成稳定、可校验的内置课程数据。
- 在 APP 内承载百家云网页播放器，并处理全屏、横屏、返回和加载失败。
- 用轻量本地存储保存课程完成状态和可用的最近播放位置。
- 让单条坏数据或单条失效链接不影响其他课程浏览。

**Non-Goals:**

- 不建设用户账号、服务端 API、后台管理端或跨设备同步。
- 不解析或下载百家云原始媒体文件，不做离线播放。
- 不实现考试、证书、评论、推荐、消息推送或学习统计报表。
- 不在首版引入远程课程目录更新机制；课程变更通过重新打包 APK 发布。

## Decisions

### 1. 使用 Kotlin + Jetpack Compose 构建 Android 客户端

选择 Kotlin 和 Compose 作为绿地项目的默认 UI 与导航方案，便于用少量页面完成分类、列表、详情和播放器容器。传统 XML + Fragment 也可实现相同功能，但会增加首版布局和状态同步代码量。该选择只影响实现方式，不改变规格中的用户行为。

建议页面结构为：

    首页/分类
      -> 课程列表
          -> 课程详情
              -> 播放页（WebView）

播放器返回时回到课程详情页，详情页再返回列表页；横屏只影响播放页的屏幕方向。

### 2. 将课程清单转换为 APP 内置 JSON

保留 Excel 作为人工维护源文件，开发阶段增加一次性转换步骤，输出 assets/courses.json。JSON 中每条记录至少包含：

- categoryId、categoryName
- courseId、title
- chapterOrTopic
- description
- teacher
- titleOrRank
- durationSeconds、durationDisplay
- videoId
- playerUrl

videoId 优先从播放地址的 vid 参数提取；同一个视频 ID 可以被多个章节记录引用。缺少视频 ID 时使用稳定的 URL 哈希作为后备 ID，并把该记录标记为需要人工检查。转换器统一处理分钟数字与 HH:MM:SS 时长，同时保留原始显示值以便排查。

选择内置 JSON 而不是首版接入远程配置，是因为课程基本固定，能避免服务端、缓存和版本兼容问题。课程更新时重新运行转换步骤并发布新 APK。

### 3. 使用受限 WebView 承载百家云网页播放器

首版使用 Android WebView 打开 https 的百家云播放器页面，因为 Excel 只提供网页播放地址，暂时没有可供原生播放器使用的媒体 URL 或 SDK 配置。WebView 页面需要启用 JavaScript、DOM storage、必要的媒体自动播放能力，并实现自定义全屏回调和横屏切换。

导航策略如下：

- 初始地址只允许来自课程数据中的 https 百家云域名。
- 播放页内的同域跳转继续留在 WebView。
- 非白名单域名或外部下载链接不在 APP 内任意打开，显示返回或使用系统浏览器的受控入口。
- WebView 崩溃、网络失败、token 失效和页面加载超时都转换为可恢复的错误状态。
- 页面销毁时保存本机学习状态，返回时不强制重新从列表开始。

备选方案是接入百家云原生 SDK。SDK 能更好地暴露播放进度和全屏事件，但需要供应商账号、应用配置和额外依赖；在现有资料只提供网页链接的前提下，首版先采用 WebView，并把播放器封装成独立模块，未来可以替换实现。

### 4. 使用稳定视频 ID 作为本机进度键

定义本地记录 LearningProgress：

- videoId
- lastPositionMs（可获得时保存）
- completed
- lastOpenedAt

使用 DataStore Preferences 保存小规模键值状态，避免首版引入数据库迁移和查询层。课程详情和列表通过 videoId 读取状态；课程排序或 Excel 序号变化不会使状态错配。

WebView 不一定允许宿主可靠读取内部播放器的精确时间，因此设计采用两级策略：

1. 播放器或页面回调可用时，保存最近播放位置并在下次进入时尝试恢复。
2. 回调不可用时，仍保存最近打开时间和手动“已学完”状态，播放器从页面默认位置开始。

“已学完”由详情页提供明确的手动操作，避免把网页加载完成误判为真正看完。

### 5. 以容错数据模型隔离坏记录

课程解析层先校验分类、标题和播放地址，再把可选字段转换成 UI 可用值。无效记录不从整个目录删除：课程仍可显示，开始学习时才提示不可播放。时长解析失败时保留原始文本或显示“时长未知”。

UI 层只依赖规范化后的模型，不直接读取 Excel 列号或 URL 查询字符串。这样可以把后续换表头、调整列顺序或更换数据来源的影响限制在导入转换步骤。

## Risks / Trade-offs

- [百家云 token 失效] → 播放页可能返回访问失败；保留重试和错误提示，课程数据重新导入时原样替换 URL，并把接入正式 SDK/API 作为后续升级路径。
- [WebView 无法读取精确进度] → 不承诺首版一定能恢复秒级进度；至少保存打开状态和手动完成状态，播放器进度只在页面能力允许时启用。
- [网页播放器依赖网络或外部脚本] → 播放页显示网络错误而不阻塞课程目录；不把课程目录加载与视频播放绑定。
- [内置目录需要发版更新] → 通过固定的 Excel 转换步骤生成 JSON，发布前做记录数、视频 ID 唯一性和 URL 格式检查，减少手工改 JSON 的风险。
- [WebView 导航到非预期页面] → 实施域名白名单、HTTPS 校验和外部导航拦截，避免把任意网页当成播放器打开。
- [课程章节复用同一视频] → 以视频 ID 作为进度键，复用记录共享学习状态；列表展示仍保留各自章节信息，避免重复播放状态产生冲突。

## Migration Plan

1. 创建 Android 工程和基础导航，先使用少量固定样例数据验证页面流转。
2. 编写 Excel 到 JSON 的转换和校验步骤，导入完整课程清单。
3. 集成受限 WebView，使用一条真实百家云地址验证播放、全屏、横屏、返回和失败重试。
4. 接入 DataStore，本机验证退出、重新进入、手动完成和清除应用数据后的行为。
5. 在至少一台目标 Android 设备上进行发布前验收，生成首版 APK。
6. 首版回滚方式是重新分发上一版 APK；由于没有服务端迁移和远程配置，不需要数据库或 API 回滚。

## Open Questions

- 正式发布时的应用名称、包名、图标和签名证书由发布方确定，不影响本 change 的功能边界。
- 目标设备的最低 Android 版本如果低于默认的 API 26，可在工程初始化时下调兼容范围；这不改变课程、播放和本机进度的行为契约。
